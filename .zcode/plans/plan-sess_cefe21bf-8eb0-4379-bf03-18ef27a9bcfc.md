# 下载统计升级：KV → D1 + 明细/趋势/来源

## 背景
当前 KV 按天聚合，存不下单次下载明细，且并发会丢计数。截图里 iOS/Android 下载 Windows 应用说明大量机器人流量混在数据里。升级 D1 后明细、准确性和扩展性全部解决。

## 改动文件（仅 2 个，前端不动）

### 1. `functions/d/[[file]].js`（重写计数逻辑）
- 每次下载向 D1 表 `events` 插入一行：`ts`(毫秒时间戳)、`kind`(portable/setup)、`country`、`os`(UA 解析)、`ua`(截断 200 字符)、`ref`(Referer 域名，无则空)、`bot`(0/1 启发式标记：UA 为空或含 bot/curl/spider/wget/python 等特征)
- 表结构自动引导：首次插入前执行 `CREATE TABLE IF NOT EXISTS`（无需 wrangler 命令行）
- **降级保证不变**：DL_DB 未绑定或插入失败时照常 302 跳转，绝不挡下载
- 日界、北京时间格式化逻辑保持

### 2. `functions/d/stats.js`（重写统计页，SQL 聚合）
新增区块：
- **最近下载明细表**（最近 30 条）：时间(北京时间) | 版本 | 国家 | 系统 | 来源 | 备注——疑似机器人的行显示警告色标签
- **14 天趋势柱状图**：内联 SVG 绘制，无第三方库
- **来源统计**：Referer 排行 TOP5（直接访问单独归类）
- 新增「今日下载」卡片；保留现有：总/便携/安装/最近一次、国家排行、系统排行、每日明细表（改由 SQL GROUP BY）
- 保留：noindex、暗色单文件样式、DL_DB 未绑定时的友好提示页

不做（你未选）：自动刷新、JSON 接口。KV 旧数据（2 天 24 条）不迁移，从 D1 启用起重新累计。

## 你需要做的（上线前）
1. 仪表盘 →「存储和数据库」→「D1 SQL 数据库」→ 创建，名字随意（如 `scratch-pad-dl`）
2. 「Workers 和 Pages」→ scratch-pad → 设置 → 绑定 → 添加：类型 D1，**变量名必须 `DL_DB`**，选刚建的库
3. 推送部署后，第一次有人点下载时表自动创建，`/d/stats` 即出数据；旧的 KV 绑定（DL_STATS）之后可以解除绑定删掉
